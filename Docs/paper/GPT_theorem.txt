So the division of labor is:

Component	Job
SNN blocks	fast sparse temporal processing

ANN blocks	high-level spatial feature extraction
Detection head	bounding boxes and classes
Step 5: Optional RNN / DWConvLSTM variant
They also add a variant with DWConvLSTM modules.

Why?

The SNN captures fast dynamics from short event windows. But driving scenes also have slower temporal patterns: cars moving over several frames, pedestrians moving gradually, etc.

So the RNN variant captures slower dynamics after the SNN-ANN bridge. The paper calls this a multi-timescale model: SNN for short timescale, DWConvLSTM for longer timescale. 


Step 6: Detection head
Finally, the processed features go into a YOLOX-style detection system with:

Loss	Purpose
IoU loss	bounding box localization
classification loss	object class
regression loss	box coordinate refinement
The datasets are GEN1 and GEN4 Automotive Detection. GEN1 has car and pedestrian classes, while GEN4 includes car, pedestrian, and two-wheeler. 


Main results
The proposed hybrid model has 6.6M parameters and achieves:

Model	GEN1 mAP
Events-RetinaNet	0.34
Proposed Hybrid	0.35
EMS-RES34 SNN	0.31
Proposed + RNN	0.43
RVT-B	0.47
So the base hybrid model beats prior SNN detectors and is competitive with ANN methods, but the strongest RNN/transformer methods still perform better. The proposed+RNN version improves to 0.43 mAP while still being relatively compact at 7.7M parameters. 


Why the ASAB bridge matters
Their ablation study shows:

Variant	mAP
Without ASAB	0.30
Proposed full ASAB	0.35
So ASAB gives a clear improvement. The paper argues this is because simple spike accumulation loses useful spatial-temporal structure, while ASAB keeps temporal relations and spatial event activity. 


Hardware/energy part
A major selling point is that the SNN part can run on neuromorphic hardware. They implemented the SNN block on Intel Loihi 2.

The SNN block ran at around 1.7 W and about 1.9 ms per step, faster than the 5 ms timestep used in the architecture. They also quantized weights to int8 with little accuracy loss, reporting mAP 0.348 for float16 vs. 0.343 for int8. 


This supports the paper’s claim:

Use SNNs where they are hardware-efficient, and use ANNs where they are accuracy-efficient.
